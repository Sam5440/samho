# 中文确认计划说明

## 目的

确认计划页 /plan 用于把“下一阶段想做什么”整理成可审阅、可回传、可执行的文本。页面面向中文用户，选项描述、边界、依赖和验收标准均使用中文；代码标识、协议方法、配置字段和文件名保留原文，确保计划能够对应源码。

页面生成计划，不执行计划。勾选是范围选择，完整文本回传对话后才构成执行依据。

服务运行时访问 `/plan`；无需启动服务时，直接双击本地 `web/plan.html` 也可以使用计划生成页面。中文文档中心对应 `/docs` 或本地 `web/docs.html`。

## 页面中的状态区分

页面和导出的文本必须区分以下三种状态：

1. 已实现并验证：当前版本已有代码和测试证据，可以直接引用现状。
2. 已知限制：当前版本明确没有或只实现了子集，不能在确认计划中写成完成。
3. 待执行目标：用户本次勾选的后续工作，必须经过实现、测试和验收后才可以改为已完成。

例如，勾选“完整 MCP 可选能力”只表示把 sampling、elicitation、OAuth、tasks 等列入后续范围；当前 MCP 支持说明仍然只对已经验证的子集负责。

## 建议勾选顺序

### 1. 先选基础目标

- Pi 执行语义：模型流式响应、上下文投影/压缩、会话树与分支、重试/故障后备。
- 可靠存储与轨迹：增量检查点、索引查询、保留/轮转、故障恢复。
- 对象运行时：scope、generation、lease、quiescence 和安全热替换。

### 2. 再选协议与扩展

- MCP 可选能力：OAuth、sampling、elicitation、roots、tasks、资源订阅、completion、自动重连。
- Skill 完整策略：ignore 文件、资源解析、来源优先级、热重载、allowed-tools 权限。
- Provider 与模型分级：更多供应商、流式协议、任务质量评测、预算和失败升级。

### 3. 最后选界面与性能

- 中文网页进阶：多工作区、长会话虚拟列表、工具差异、断线恢复和任务通知。
- TUI：快捷键、主题、长会话虚拟列表、中文/宽字符验收。
- 性能与可靠性：同机 Pi/Rust 对照、大会话、工具并行、24 小时 soak、崩溃注入。

页面应提示依赖关系。例如，热替换依赖对象代际和调用排空；MCP OAuth 界面依赖认证状态模型和安全凭据存储；完整轨迹复盘依赖事件 schema 版本、索引和保留策略。

## 导出文本的固定内容

下载文件建议按以下顺序生成：

1. 标题、生成日期、项目版本和计划格式版本。
2. 当前已实现能力摘要，以及对应测试/报告路径。
3. 当前已知限制和明确未支持项。
4. 本次勾选的目标清单，每项含目的、依赖、影响文件或模块、验收测试、回滚条件。
5. 执行顺序、阶段门槛、预计需要的外部配置（模型端点、API key 环境变量、MCP server）。
6. 明确列出未勾选项目和不纳入本次范围的内容。
7. 执行规则：网页不自动执行；用户回传完整计划后才开始；执行中出现依赖缺失或测试失败时暂停并回报。
8. 用户备注和确认栏。

文件名固定为：

```
samho-确认执行计划-YYYY-MM-DD.txt
```

使用 UTF-8；为兼容 Windows 文本工具可以带 UTF-8 BOM。日期使用生成当天的本地日期，不能把日期写死在网页源码中。

## 回传格式

用户下载文件后，将完整文本原样粘贴回当前对话。不要只回复“确认”或只发送勾选项，因为完整文本包含已实现基线、限制、依赖和验收条件。收到完整文本后，执行者应：

- 先复述本次范围和不包含的项目；
- 检查依赖、文件路径和命令是否仍有效；
- 按阶段修改代码和文档；
- 在每个阶段运行对应测试；
- 将实际结果、未完成项和新风险写回对话；
- 只有全部验收条件满足，才把计划项标记为已完成。

真实模型调用、外部消息或部署等动作，以计划中的明确设置和本对话已有授权为准。不要在文本中写入 API 密钥值；使用环境变量名称表示凭据来源。
