# Samho 中文使用说明

## 这是什么

Samho 是 Pi coding agent 的 Rust 重写框架。它通过统一 Object 注册表管理 Agent、模型、工具、MCP 服务、Skill、Session 和 Task，并提供会话与调用轨迹存储。网页工作台和 Ratatui TUI 共用一个 Rust 服务。

当前版本是可运行的增量重写版本。默认模型是明确标记为 [DEMO simulation] 的离线模拟器，不会发送真实模型请求。模型层级、工具权限、预算、日志和轨迹边界都由配置控制。

## 启动网页工作台

需要 Rust 1.88 或更高版本；MCP stdio 集成测试还需要 Python 3。

```powershell
cargo run -p samho -- serve --bind 0.0.0.0:7432
```

本机打开 http://127.0.0.1:7432；启动日志会列出局域网地址，网页顶栏也会显示可复制的「局域网 http://<IP>:7432」。只希望在本机访问时用 `--bind 127.0.0.1:7432`。服务没有身份认证，请只在可信局域网使用。网页标题、按钮、状态、路由说明和检查器均为中文；协议名称和代码标识保留英文，方便与日志和配置对应。

也可以直接双击本地 `web/docs.html` 阅读离线中文文档，或双击 `web/plan.html` 勾选并生成确认计划。两页不依赖运行中的 Rust 服务；网页工作台的真实任务功能仍需先启动服务。在线入口分别为 `/docs` 和 `/plan`。

另开终端可以连接同一个运行时：

```powershell
cargo run -p samho -- tui --url http://127.0.0.1:7432
```

网页与 TUI 共用会话、并发限制、模型决策、对象注册表、任务进度和轨迹。服务关闭后，运行时会释放数据目录锁；恢复任务不会盲目重放已经产生外部副作用的调用。

## 通过网页执行任务

1. 在任务输入框写下目标。
2. 保持“自动分级”，让路由器按照复杂度、能力、预算和延迟选择模型；也可以选择 nano、fast、balanced、reasoning、frontier 或 specialist。
3. 如需固定物理模型，从“模型”下拉框选择；固定模型会覆盖自动选择。
4. 在 Skill 面板勾选本次任务要显式加载的技能。
5. 提交任务。右侧轨迹面板会显示路由理由、模型调用、工具调用和最终状态。
6. 需要停止时点击“停止执行”。取消只停止后续派发，已经发送到外部服务的副作用可能仍需人工核对。

模拟输出会显示 [DEMO simulation]。它只用于验证流程，不代表模型质量。

## 通过命令行执行与复盘

```powershell
cargo run -p samho -- run "/demo read README.md" --complexity 2 --json
cargo run -p samho -- inspect
cargo run -p samho -- replay --export trace.jsonl
```

run、inspect 和 replay 会打开本地数据目录。服务运行时应使用网页/TUI 访问同一运行时，或为独立 CLI 指定另一个数据目录。两个进程同时写同一目录会被文件锁拒绝。

## 创建中文可编辑配置

```powershell
cargo run -p samho -- config init samho.toml
cargo run -p samho -- --config samho.toml serve
```

生成的 TOML 默认接入本机 Anthropic 协议网关（http://127.0.0.1:3425，模型 auto/glm-5.3-flash），字段保持英文以便程序校验；逐项中文解释见[自定义配置说明](customization.md)。使用前先设置密钥环境变量 `SAMHO_API_KEY`（默认模板对应 `magpie`）；API key 只通过环境变量读取，不写进配置文件。其他真实 Provider 示例见 examples/samho.chat.toml（OpenAI 兼容）与 examples/samho.anthropic.toml（Anthropic 协议完整示例）。

## 测试端口约束

本地协议 fixture、OAuth 回调、Web smoke 和 Chrome CDP 验收只使用 300–400 端口；Rust 测试分配器会在 301–399 保持监听。生产服务端口仍可按配置自定义。详见[测试端口策略](test-port-policy.md)。

## 网页确认计划：勾选后再执行

访问网页的 /plan 页面，阅读已实现能力与待实现目标，勾选希望纳入下一阶段的项目，填写模型、平台、MCP、Skill、日志和测试约束，然后检查生成文本。

网页生成的是 UTF-8 文本文件，文件名为：

```
samho-确认执行计划-YYYY-MM-DD.txt
```

页面只生成和下载文件，不自动修改源码、不调用模型、不启动工具、不部署服务。文件中会明确区分：

- 当前已经实现并通过验证的能力；
- 当前存在的限制；
- 本次勾选的待执行目标；
- 必要依赖、执行顺序、验收条件和回滚/暂停条件；
- 未勾选项目，避免把它们误认为本次范围。

请将下载文件的完整内容粘贴回本对话。收到后，执行将以该文本为范围依据；在此之前，勾选内容只是一份本地计划，不会自动执行。确认计划页面的字段和生成规则见[中文确认计划说明](中文确认计划说明.md)。
