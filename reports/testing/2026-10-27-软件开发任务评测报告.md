### 耗时与效率观察

- **GLM-5.3-Flash 明显更快**：6 个从零跑完的任务平均 **222s**（121–234s），而 gpt-6-astra 系 5 个任务平均 **690s**（597–892s），约 3 倍差距。

## 三、断点继续能力（三次真实实验）

评测期间发生两次基础设施中断 + 一次框架上限中止，全部转化为断点恢复实验：

| 实验 | 中断原因 | 恢复方式 | 结果 |
| --- | --- | --- | --- |
| T03 | 会话续接导致 serve 进程死亡 | 新进程 POST /api/run + session_id + 续跑提示 | ✅ 10 轮完成，全维 PASS |
| T05 | 同上，Rust 任务进行中（盘上已有半成品） | 同上，提示词强调"勿推倒重来" | ✅ 14 轮 187s 完成收尾，全维 PASS |
| T10 | `max_turns=30` 上限中止（非故障） | 同一会话继续，提示列出剩余交付 | ✅ 7 轮完成合并/清理，git 全绿 |

**结论：RPi 的会话级断点恢复对真实开发任务有效。** 模型能从 git 状态与磁盘产物准确推断进度（T05 在 Cargo.toml/src/tests 已存在的情况下没有重写，直接续写并补齐 git 流程）。恢复的关键是提示词给出「先查看目录与 git log 评估进度」的显式第一步。局限：任务注册表在内存中，进程重启后任务 ID 404，必须以会话为锚点恢复（语义正确，但运维上需要记录 session_id）。

## 四、模型切换事件记录

用户指令：全部执行模型改为 GLM5.3Flash，gpt-6 系列仅作任务规划。执行时发现：

1. 网关上原 GLM 通道 ID `glm-reasoning` **当日下架**（"No available channel for model glm-reasoning under group svip"）；
2. 大写 `GLM-5.3-Flash` 同样报上游错误；`glm-5.3-flashx` 无套餐权限；**唯一可用的是小写 `glm-5.3-flash`**；
3. RPi 模型 ID 大小写敏感且必须在配置 `[[models]]` 中注册——改配置后需重启 serve 才生效（冒烟验证通过后才开始跑批）；
4. 切换后 GLM 阶段 7 个任务无一次网关级失败（限流/超时均未出现），通道稳定。

## 五、T10 失败分析（唯一 FAIL）

**经过**：首跑 30 轮触发 `max_turns` 上限被中止——此时表征测试、两步重构提交、README 均已完成，测试全绿，但 feature 分支未合并、工作树未清理。断点恢复 7 轮完成合并与清理后，git 五项全绿，唯一剩余不合格项：**ci.yml 的测试步骤用 `pip install pytest` + `pytest -q`，而任务书指定测试命令为 `python -m unittest -v`**（恢复提示中已显式要求 unittest 步骤仍未改）。

**判定**：按预登记验收标准（python 栈 CI 须含 unittest 测试步骤）判 FAIL。客观说明：pytest 能收集并运行 unittest 用例，该 CI 在真实 GitHub Actions 上大概率是绿的；且模型把 `expected_output.txt` 行为校验写进了 CI 步骤（超出要求的加分行为）。故这是**合规性失败而非功能性失败**——框架/模型在次要交付项上对显式指令的遵从度不足，主目标（合并/清理）完成后即认为任务结束。

**框架层启示**：
1. `max_turns`（配置默认 30）对「多步重构+完整 git 流程」类任务偏紧，复杂任务建议 40+ 或按 complexity 动态放大；
2. 轮次耗尽后任务标记 failed 而非 paused，但会话完整保留——「恢复继续」是比「整任务重跑」更合理的补救（本次 89.6s vs 重跑预估 300s+）；
3. 建议框架在任务收尾阶段注入交付清单核对提示（merge/clean/CI 一致性），可显著减少此类尾巴失败。

## 六、验收方法与可信度

每个任务的 PASS 由独立验收器判定，含五道硬校验：
1. **结构**：README、`.github/workflows/ci.yml`（on/jobs/checkout/与栈匹配的测试步骤）、测试文件存在；
2. **git**：`rev-list` 计数 ≥3、提交主题匹配 Conventional Commits 正则、feature 分支存在且 `--merged` 主干、`status --porcelain` 为空；
3. **测试**：验收器亲自执行项目测试命令（`python -m unittest -v` / `node --test` / `cargo test`），不采信模型自述；
4. **CI 模拟**：按栈执行等价步骤（compileall / `node --check` / `cargo fmt --check` + `clippy -D warnings`）+ 测试；
5. **守卫**：fixture 任务（T08/T09/T10）的受保护文件 SHA-256 不得变化——T10 的 `expected_output.txt` 全程未被篡改，行为保持由字节级比对确认。

## 八、总体评估

- **RPi 框架成熟度**：12/12 任务的完整开发流程（含 2 次进程死亡、1 次轮次上限）中，框架本身零崩溃、零数据丢失；断点恢复三次全部成功。服务层可靠性在真实长时间负载下得到验证。
- **GLM-5.3-Flash 作为执行模型**：6/7 PASS，速度快约 3 倍、输出精炼、通道稳定；短板是次要交付项的指令遵从（T10 CI 命令）。**性价比显著优于 gpt-6 系**，适合作为日常执行模型；复杂任务可保留 gpt-6 系作规划/审查角色。
- **评测方法**：独立验收（不信任自述）再次证明必要——T09 试点期曾因执行器 bug 误报，T10 模型在回复中自称完成但实际未合并分支；只有亲跑测试、解析 git 才能得到可信结论。
