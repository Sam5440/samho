## 4. 缺陷清单与修复证据（P4）

> 协议：每个缺陷按「现象 → 根因 → 修复 → 验证」记录，修复一律附带回归测试。

### D-001 SSE 尾帧被误判为协议错误（阻断 GLM 全系模型）

- **现象**：任何 GLM 模型任务报 `provider Protocol: SSE choice continued after finish_reason`，任务失败。
- **根因**：网关在 `finish_reason` 之后仍发送尾帧（空 delta choice + 仅含 usage 的帧），`StreamAccumulator` 将任何后续 choice 视为违规。
- **修复**：`provider.rs` 新增 `choice_contributes()`——尾帧若不携带文本/思考/工具调用则容忍；携带贡献性载荷仍拒绝。finish_reason 只发一次。
- **验证**：回归测试 `accepts_reasoning_alias_and_empty_tail_frames_after_finish_reason`；GLM reasoning 模型真实任务完成。

### D-002 GLM 思考内容（`reasoning` 键）被静默丢弃

- **现象**：思考模型的推理过程不进入事件流/会话。
- **根因**：网关使用 `reasoning` 键，实现只识别 `reasoning_content`。
- **修复**：`reasoning_fragment()` 同时接受两键（`reasoning_content` 优先），类型错误显式报协议错误。
- **验证**：回归测试覆盖别名键；GUI 轨迹可见思考链路。

### D-003 网关嵌入错误体被分类为不可重试

- **现象**：上游闪断时任务直接失败（`provider SSE error: upstream_error`），重试机制未介入。
- **根因**：OpenAI 兼容网关会在 2xx 响应内嵌 `error` 对象；原实现只把 HTTP 状态映射错误类别。
- **修复**：`decode_completion()` 先检查 `error` 字段，`embedded_error()` 按错误 `type` 分类（server/api/upstream→Server 可重试；rate_limit→RateLimited 可重试；其余→Protocol）。
- **验证**：两个回归测试（流式/非流式）；真实 frontier 任务经重试成功。

### D-004 思考词元超出预留导致任务在成功边缘中止

- **现象**：`provider usage exceeded reservation; actual usage recorded, no further dispatch`——思考模型的实际词元（含无界思考）超过 `输入 + max_output` 预留，任务被终止。
- **根因**：网关不把 `max_tokens` 应用于思考词元，预留公式未考虑思考开销。
- **修复**：`ModelDescriptor` 新增 `reasoning_reserve_tokens`（缺省：思考模型 = max_output ×2），`budget_output_reserve()` 统一用于 USD 与词元预留。
- **验证**：回归测试 `reasoning_models_reserve_thinking_tokens...`；GLM 长任务（F4-b 会话延续）完成。

### D-005 极端超额仍会中止任务（与"记账告警"语义冲突）

- **现象**：小窗口配置下真实用量即使被预留公式覆盖不足时仍触发中止。
- **根因**：`settle()` 超额即 `bail!`，而服务端上报时超出已真实发生，中止只会留下不一致状态。
- **修复**：`settle()` 改为持久化真实账目 + 返回是否超额；agent 循环发 `budget.overage` 事件后继续任务；派发前硬顶（ceiling）不变。
- **验证**：脚本化轻/重超额两分支测试；真实小窗口任务完成并留下告警事件。

### D-006 多工作区路由未实现（GUI 切换必然 404）

- **现象**：配置 `[[workspaces]]` 后 `/api/workspaces` 正确返回附加工作区及 `/w/{id}/` 跳转 URL，前端下拉渲染正常，但访问 `/w/aux/` 返回 404——切换工作区必然失败。
- **根因**：服务端只注册了 `/api/workspaces`，从未挂载 `/w/{id}` 路由；多工作区只完成了配置校验与 API 声明（前端 `apiPath` 已按前缀转发）。
- **修复**：`server.rs` 新增 `attach_workspaces()`——为每个附加工作区构建**独立 AgentRuntime**（独立 data_dir/会话/事件/预算），`Router::nest` 到 `/w/{id}`；axum 0.8 的 nest 不匹配尾斜杠路径且路由匹配先于中间件执行，故在 fallback 对 `/w/{id}/` 做 308 重定向；服务关闭时逐一 shutdown 附加运行时。
- **验证**：回归测试 `workspace_prefix_serves_isolated_runtime_and_unknown_ids_404`（页面/API/隔离/未知 id 404）；真实端到端——aux 工作区提交任务（sol-nano 回复"多工作区正常"），aux 会话 1 条与默认工作区 10 条完全隔离。

### 环境记录（非缺陷）

- ZCode 内置浏览器截图后端故障（两次捕获失败），F11 证据改用 DOM/文本快照记录；建议 CI 场景使用 CDP 截图。
- Playwright `press("Control+Enter")` 无法触发快捷键提交；页面原生 `KeyboardEvent(ctrlKey)` 验证通过，属自动化模拟差异，非产品缺陷。
- GUI「导出中文复盘」使用 `window.open(_blank)`，在自动化浏览器中被拦截；端点本身验证通过（200 + `content-disposition: attachment; filename=Samho-trace.md` + 完整 CSP 头）。

## 8. 遗留风险与建议

1. **思考词元预留是启发式**（默认 max_output ×2）：极端思考模型仍可能触发 `budget.overage` 告警（任务继续，账目准确）。建议按模型在配置中显式设置 `reasoning_reserve_tokens`。
2. **TUI 真实终端交互**未纳入自动化（需 PTY）；本次以契约端点 + 结构化响应验证，建议发布前人工过一遍键盘流。
3. **功能差距路线**（对标 oh-my-pi/opencode）：优先补 LSP 集成（诊断进上下文）与子代理（并行扇出）；Hashline 编辑与持久记忆次之。
4. **多工作区**已可用但每工作区独立运行时各自启动 MCP 子进程，工作区数量大时进程数线性增长，可考虑共享 MCP 连接池。
5. GUI 导出按钮依赖 `window.open`，若未来嵌入受限 iframe 环境，可改为 `a[download]` 触发。
